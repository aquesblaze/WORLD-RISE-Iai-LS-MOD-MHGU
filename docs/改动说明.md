# v1.0.7 改版说明（全风格 + 居合纳刀 + 无敌帧 +2 帧）

基于官方 **MHW-LS-MHGU-Source-v1.0.7**，三处改动；完整 diff 见 `docs/全风格居合无敌帧.diff`。

## 一、全风格可用

`c/gu_adapter.c`：

```c
/* 官方 */
static unsigned local_guild(void *a)
{
    if(!a||word(a,0)!=main_base+VT||!(word(a,0x13cc)&1))return 0;
    return ((int (*)(void *))(main_base+0x268818))(a)==0;
}
/* 本改版 */
static unsigned local_ls(void *a)
{
    if(!a||word(a,0)!=main_base+VT||!(word(a,0x13cc)&1))return 0;
    int style=((int (*)(void *))(main_base+0x268818))(a);
    return style>=0&&style<=5;
}
```

同步改名全部调用点（gu_adapter.c 9 处、world_adapter.inc 4 处、world_camera/detector/physics.inc 各 1 处）。
机器码核对：`cmp r0,#5 / movhi 0 / movls 1`。

## 二、Rise 化 ISS 派生（原「居合后能接纳刀居合」已替换）

旧的 `world_sheathe_chord()` / `WORLD_IAI_SHEATHE_GRACE` / `sheathe_latch` 已移除：
小居合/大居合不再任意帧 ZR+B 无限循环回特殊纳刀。

按键说明：这里的 ZR 是 Switch 右扳机（`gu_adapter.c` 读 `raw&0x800`，内部符号 `ML_R`），
GU 原生 R 肩键保持不变，只用于系统功能。

当前 `c/world_command_driver.inc` 的规则：

- 普通地面招式仍按源 TIML 的 `WI_SHEATHE` 窗口用 ZR+B 进特殊纳刀。
- `W_BIG` counter 成功后，ZR+B → `W_SHEATHE`（成功的专属派生），或直接单按 B → roll。
- ISS 的四种派生共用 F70 门限，早按都锁存到 `follow_ready`：bit0=单按 ZR（Spirit III），bit1=ZR+A（Foresight），
  bit2=ZR+B（Special Sheathe），bit3=单按 B（roll）。四种派生都需要 counter 成功，whiff 只能正常收招。
  ZR/B 另加 2 帧 debounce：ZR 按住或松开、B 按住都必须连续 2 个采样才认，避免 ZR+B 与单按 B 在边界帧互相误判。
  单按 ZR / 单按 B 还要在 F70 后再等 `W_ISS_CHORD_GRACE`（10 帧）才兑现：ZR 先按、B 晚到仍算 ZR+B，
  不会被抢成 Spirit III；B 先按、ZR 晚到同理合流成 ZR+B。单按 ZR 的宽限还会从 ZR 自己的按下帧重新起算
  （`iss_zr_frame`），所以 F70 之后才按下的 ZR 也能等满整个窗口；伙伴键先按住、ZR 后按同样成立。
  ZR+B / ZR+A 成立后立即发动，不再等这 10 帧。
  ZR 兑现为 `ground_enter(s,o,36,ML_R)`；counter 通常在 F12～F14 成立，所以早按并松开的 ZR 也必须缓冲，
  否则 F70 时上升沿已经消失；同时 F20→F70 的延迟避免 Spirit III 切断 ISS 回收动画。源生成的辅助节点 36 保留 `124 → 108`（F9）起手段，
  落到节点 2（气刃斩 III，扣 20 练气）；
  再按一次新的单按 ZR → 节点 2 的原生 ZR 边在源 108 F110 窗口发动作 30（气刃大回旋斩，练气≥25）。
- `W_BIG` counter 成功时，ZR+A → `W_FORESIGHT`（whiff 不再触发）。节点 65 没有这两条边，公共转移又排除
  `node==65`，所以由命令层直接用按键边沿处理；ZR 可沿用按住的那一下，只看伙伴键的新边沿，
  且 A 的早按同样会锁存到 F70 才发动。
- `W_SHEATHE` 里大居合仍要求一次新的 ZR 按下（`fresh=b->held&~s->consumed`），防止用 ZR+B
  进纳刀后仍按着 ZR 而自动送出一发大居合。

原版数据走不通的原因：节点 64/65 没有指向 61 的边；公共转移被 `node!=0&&node!=64&&node!=65` 排除；
这两段 TIML 里 ZR+B 权限位所有帧为 0。

## 三、居合无敌帧判定（与另一版一致）

`world_damage()` 里的判定仍是"当前 TIML 事件的 `common` bit26"，但把这段连续事件窗口的最后两帧排除：

```c
/* 命中时沿同一 source 往后走到这段 bit26 窗口的最后一个事件 */
iai = f <= last - 2.0f;
```

窗口：小居合 ~5→3 帧；大居合（308）约 12→10 帧；大居合（309-311）约 14→12 帧。
原来"+2 帧延后"的 `WORLD_IAI_INVULN_EXTEND` 机制已移除（含 `world_iai_invuln_ext` 日志）。

## 四、Rise 化 ISS 与 Iai stance 方向回避

- `c/world_command_driver.inc` 的 `W_SHEATHE` 分支：
  `fresh=b->held&~s->consumed` 排除进纳刀时那一下 B；另外要求 `event->phase==1`
  （源 306 从 F73 起，收刀根位移已结束、stance 真正就位）。早按 B 不缓冲、不截断动画；
  就位后新按 B（且不按 ZR）才直接发出 `W_ROLL`。heading 取
  `magnitude>=50 ? input_heading : heading`，摇杆有输入时沿摇杆方向回避，回中则保持当前朝向。
- 源 306 的 TIML 没有 `WI_ROLL` 权限位，因此这里不等待源窗口；
  `world_commit()` 的 `W_ROLL` 分支仍通过 `virtual_request(a,1,6,12)` 走原生回避。
- Rise ISS 规则：`c/world_core.c` 只在 `o->counter` 成立时发 `rank_delta=1`；
  whiff 不再发 `rank_delta=-1`。
- 升级不再清槽：删除 `c/world_adapter.inc` 每帧监控 `actor+0x3330` 上升就清 `0x2780`
  的逻辑；连段大回旋开刃的 `gauge_clear/gauge_hold` 也移除。
- ISS 后派生：`c/world_command_driver.inc` 的 `W_BIG` 分支用原始按键边沿补上
  counter 成功后 ZR+B → `W_SHEATHE`（F70 起），或直接单按 B → roll（F70 起，whiff 不触发）；
  counter 成功后 ZR+A → `W_FORESIGHT`（F70 起，whiff 不可），以及 counter 成功后新的单按 ZR → 气刃斩 III → 气刃大回旋斩（F70 起）。
  四种派生统一延后到 F70，避免切断 ISS 回收动画；早按都会锁存，到点才兑现。
  节点 65 自身没有前两条边，所以由命令层直接处理；
  ZR+B/ZR+A 允许沿用按住的那一下，只看伙伴键的新边沿；气刃斩 III 要求 ZR 本身也是新的按下，
  四种派生的按键边沿都会在 F70 前先锁存，避免 counter 刚成立时的快速按键丢失。
- 气刃斩 III 的源 108 在 F90 打开 command39 缓冲窗口、F110 打开 execute，节点 2 的 ZR 边
  （property0 AND 练气≥25）会在 F110 正常触发，所以第二段完全交给源 FSM 路由到动作 30，
  不需要自定义桥接；只复用了原本未使用的 `WState.follow_ready` 做早按缓冲，`w_leave()` 会清除。
- `c/world_adapter.inc` 的 `world_motion_speed()` 保留 0x5d/0x13a/0x117/0x129
  四个 Quick Sheathe 技能 ID，把原 1.16f 改成 1.40f，只作用于特殊纳刀起手段。
- `WState` 复用了原本未使用的 `follow_ready` 做 ISS 收尾早按缓冲（bit0=ZR，bit1=ZR+A，bit2=ZR+B，bit3=B），
  并新增 `iss_r_held / iss_r_clear / iss_b_held` 三个计数做 ZR/B 2 帧 debounce；`w_leave()` 会一并清零。
  `helm_air_armed` 仍只服务登龙下劈。
- `c/world_core.h` 新增 `W_ISS_CHORD_GRACE=10`；`W_BIG` 里单按 ZR / 单按 B 的兑现条件改为
  `frame>=70+W_ISS_CHORD_GRACE`，且单按 ZR 还会再与 `iss_zr_frame+W_ISS_CHORD_GRACE` 取较大值，
  让 ZR 在 F70 之后才按下时也能等满整个窗口。ZR+B / ZR+A 分支仍在 F70 立即生效；
  伙伴键先按住、ZR 后按也会在 ZR 边沿组成 ZR+A。
- **气刃大回旋原生镜头推拉已关闭**（`c/world_camera.inc`）：日志证据显示气刃大回旋
  （原生 motion `0x57F`，source 109）自带约 104 帧的镜头 work：FOV 50° → F19 44.8° →
  F33 65.5° → F104 50°，且 GU 在换动作时以当前值为起点重播，所以会延续到世界招式并在
  换动作时跳变。现在在整个气刃动作（action `0x1E`）、所有世界私有动作、以及最后一个之后
  110 帧内，把 `camera+0x3c` 直接钉到静止 FOV（默认 50°）。静止值只从真正平坦的镜头学习
  （单帧变化 <0.02° 且连续 12 帧），work 在 65.5° 峰值附近每帧仍变化约 0.04°，不会被误采。
  钉住不做缓动（缓动本身就是可见的缩放）；过场动画、非长刀角色和窗口之后不受影响。
  新增 `world_lens_leak` 探针（偏离静止值 >0.5° 时边沿触发，上限 64 行）用于验证。
- `build.rs` 支持 `ARM_NONE_EABI_GCC`；链接器用 `CARGO_TARGET_ARMV7A_NONE_EABI_LINKER`。
- 安装日志 `installed; all styles; iai roll; sheath x1.40; iframe-2; native collision retained; rumble; chord-grace; lens-off`。

## 八、登龙落地接 Sakura Slash I（本次新增）

发现日志（`log/log.txt`）中，按住 R+A+B（狩技槽 1）后 GU 依次请求：

```text
native_request 0C148CA0 00000010 00000033 00000040   # 动作 51（0x33），flags 0x40
native_state   0C148CA0 00000033 00000701 ...
native_request 0C148CA0 00000010 00000036 00000000   # 动作 54（0x36）
native_state   0C148CA0 00000036 00000702 ...
native_request 0C148CA0 00000010 0000003E 00000000   # 动作 62（0x3E）
native_state   0C148CA0 0000003E 00000703 ...
```

动作 51 的请求 flags 是 `0x40`，后续 54/62 是动作处理器内部的链式请求，不是另一次狩技激活。
因此插件只需要复现第一次请求，不需要装备狩技，也不需要狩技槽充满。

实现：

- `c/world_core.h`：`WDecision` 增加 `native_flags`，保留显式请求 flags；
  新增 `W_ART_SAKURA_SLASH=51`、`W_ART_SAKURA_FLAGS=0x40`；
  `WState` 增加 `land_r_clear`，记录 ZR 已经松开的采样数；新增 `land_zr_wait` 与
  `W_LAND_CHORD_GRACE=10`，给落地单按 ZR 留出合流窗口。
- `c/world_command_driver.inc`：
  - 每帧维护 `land_r_clear`（按住 ZR 归零，松开最多累计 3）。
  - `W_LAND` 分支：`land_armed`（松开 ≥2 帧）且本采样出现新的单按 ZR
    （`fresh&ML_R`，且没有 X/A/B/Y/ZR 伙伴）时先锁存 `land_zr_wait=W_LAND_CHORD_GRACE`，
    不立刻出招；宽限内出现 ZR+B 直接进特殊纳刀、ZR+A 直接接看破斩（B/A 先按住、ZR 后按同样成立），
    窗口走完仍只有 ZR 才 `w_leave()` 并返回
    `W_NATIVE / native_action=51 / native_flags=0x40`。
    这样“想按 ZR+B 但 ZR 先到”不会再被误判成 Sakura。
  - 下劈用的 ZR 在进入 `W_DOWN` 时已被 `enter(...,ML_R)` 消耗；再加上
    `land_r_clear` 要求先松开，所以落地一直按住 ZR 不会误触发。
  - A/B/X/Y 的落地派生（特殊纳刀、看破斩）仍走原来的源图，不受影响。
- `c/world_adapter.inc`：`W_NATIVE` 分支优先使用 `d.native_flags`，
  只有旧路径没有显式 flags 时才回落到 `0x8000`/`0x1000`。
- 请求仍然走 `virtual_request(a,16,51,0x40)`，`submitting` 保护下不会被
  `world_request()` 当成普通攻击拦截；之后 54/62 由 GU 原生处理器自行请求。

### 使用代价：扣 1 级练气（本次新增）

原版 Sakura Slash I 的斩击会给剑升 1 级练气。本改版把它改成消耗：使用后**扣 1 级**。
同时按《世界》的节奏加了**等级门槛：只有黄色（2 级）才能发动**。

- `c/world_core.h`：`WState` 增加 `sakura_stage/sakura_rank/sakura_frames/sakura_grace/sakura_paid`
  与拒绝记录 `sakura_denied`；动作常量增加 `W_ART_SAKURA_SWEEP=54`、`W_ART_SAKURA_FINISH=62`。
- `c/world_command_driver.inc`：落地 ZR 派发动作 51 前先算「兜割扣级之后」的等级
  （`helm_cost_pending` 还没结算时先减 1），只有等于黄色 2 才派发，否则只记
  `sakura_denied=等级+1`、不派发也不扣级。派发时记录基线
  （`sakura_rank=o->rank+d.rank_delta`），`sakura_stage=1` 等待原生动作链。
- `c/world_core.c`：每帧检查原生动作链（动作 51/54/62 或 motion `0x701..0x703`）。
  - 状态机放在「就绪/拔刀」判定**之前**：实测动作链结束那一帧 GU 会短暂报告
    未就绪/未拔刀，旧代码在该帧把待扣等级清掉。
  - 链真正开始后 `sakura_stage=2`；若此时等级高于记录值（原版升了级），
    返回 `rank_delta = sakura_rank - 当前等级` 立刻抵消。
  - **扣级在动作链开始那一帧就结算**（`sakura_paid` 保证只扣一次）：先按旧基线
    抵消原生升级，再扣 1 级。所以等级随招式发动一起下降，不再等动画播完。
    实测发动到链开始约 2 帧（≈33 ms），旧版要等整套动作结束（≈1.5 s）。
  - 链结束后连续 6 帧未再出现只用于收尾状态机，不再扣级。
  - 若 90 帧内根本没出现原生动作链（请求被游戏拒绝），直接放弃，不扣级。
  - 0 级时只抵消原版升级（如果有），不扣成负数；角色死亡时直接放弃，不扣级。
- `c/world_adapter.inc`：`world_pay()` 应用等级变化前记录
  `world_rank_pay <actor> <delta> <当前等级>`；`sakura_denied` 记录
  `world_sakura_denied <actor> <实际等级> <兜割扣级是否还没结算> <基线>`，方便确认门槛。
- 只作用于本插件的落地派生；正常装备在狩技槽里使用的 Sakura Slash 仍是原版升 1 级。

等级走向（与《世界》一致：红 → 兜割 → 黄 → Sakura → 白）：

| 兜割前 | 落地扣级后（判定用） | 能否接 Sakura | 结束后 |
|---|---|---|---|
| 红 3 | 黄 2 | 能 | 白 1 |
| 黄 2 | 白 1 | 拒绝 | 保持白 1 |
| 白 1 | 无 0 | 拒绝 | 保持无 |
| 无 0 | 无 0 | 拒绝 | 保持无 |

所以「兜割 + Sakura」这套派生要从**红刃**起手：兜割先付 1 级到黄，Sakura 再付 1 级到白。

验证方法：安装日志应带 `foresight-win` 标记。落地后按 ZR，日志应出现
`world_native_follow 0C148CA0 00000033 ...`，随后 `native_state` 出现
`00000033/00000036/0000003E` 与 `00000701/00000702/00000703`。等级变化应出现
`world_rank_pay`：链开始那一帧同时有抵消和扣级（命中时通常是 `FFFFFFFE`，未命中是
`FFFFFFFF`；若原生升级晚一帧才出现，会看到两次 `FFFFFFFF`），动作结束时不再有额外的 `-1`。
`world_sakura_stage` 记录状态机（`1` 等待原生链 → `2` 链中/收尾 → `0` 结束），
打包字段为 `drawn<<16 | ready<<8 | grace`；正常一次使用应看到 `1 → 2 → 0`，
且扣级发生在 `1 → 2` 那一帧。
在非黄色时按 ZR 会看到 `world_sakura_denied`，且不会出现 `world_native_follow`。

## 手柄震动（本次新增）

`c/world_rumble.inc`：居合 GP 成功与登龙首次命中时触发原生手柄震动。
插件不能直接调 SDL，因此用 main 的 GOT 槽反推 sdk 基址，再调用
`nn::hid::detail::SendVibrationValues`：

- `sdk_base = *(u32 *)(main_base + 0x1848534) - 0x25c664`
- 调用入口 `sdk_base + 0x253290`，参数 `(handles, values, count)`
- 句柄来自 `main_base + 0x1848650`（游戏自己的 GetVibrationDeviceHandles 导入）
- 只走复数命令 206（重编译版只实现这一条；单数 201 会被忽略）
- 触发点：`world_counter_accept()`（仅大居合 W_BIG，0.9 强度 9 帧）、
  `world_follow.inc` 首次弹壳命中（0.8 强度 8 帧）；每帧 tick 发送，结束时补 0
- 安全：prologue 校验 `0xE92D48F0` + 页对齐检查；不通过自动关闭，不会乱跳
