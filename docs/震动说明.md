# 手柄震动说明（居合 GP 成功 / 登龙命中）

## 触发时机

| 事件 | 触发点 | 震动强度 | 时长 |
| --- | --- | --- | --- |
| 居合 GP 成功（大居合反击挡下攻击） | `world_counter_accept()` | 0.9 | 9 帧（≈0.15s） |
| 登龙命中（第一段真实接触） | `world_follow.inc` 延迟弹壳命中怪物 | 0.8 | 8 帧（≈0.13s） |

每次只震一次：登龙七段命中只在**首次实际接触**时震，不会连续震七下；GP 由
`world_counter_seen` 去重，一次反击只震一次。震动结束后会补发一次 0 值停止马达。

## 实现方式（不能直接调 SDL）

插件跑在游戏的 ARM 代码里，接触不到宿主的手柄 API，所以必须走游戏自己的 HID 通路。
主模块 main **没有**导入 `nn::hid::SendVibrationValues`，它导入的是 SDK 的震动图
（VibrationPlayer / VibrationTarget / VibrationWriter），加载器会把这些导入解析到
main 的 GOT 表里。于是任意一个 GOT 槽都能反推出 sdk 模块基址：

```
sdk_base = *(u32 *)(main_base + 0x1848534) - 0x25c664     // VibrationWriter::Write
```

拿到 sdk 基址后直接调用 `nn::hid::detail::SendVibrationValues`（sdk + 0x253290），
参数是 `(VibrationDeviceHandle*, VibrationValue*, count)`。句柄来自游戏自己的
`GetVibrationDeviceHandles` 导入（main + 0x1848650），所以和游戏原生震动写的是同一组设备。

`VibrationValue` 是 4 个 float：低频振幅、低频频率、高频振幅、高频频率；振幅 0..1。

### 为什么用「复数」版本

PC 重编译版（MHGURecomp）的 HID 服务只实现了命令 **206 = SendVibrationValues**：
它取所有值里最大的低频/高频振幅，乘 65535 交给 `input_set_rumble`，再经 SDL 震动。
单数命令 201（SendVibrationValue）在服务里没有分支，会被直接忽略，所以必须走复数版本。

### 安全性

- 先做 prologue 校验：`sdk + 0x253290` 处第一条指令必须是 `push {r4,r5,r6,r7,fp,lr}`
  （`0xE92D48F0`），游戏版本不符时直接放弃，不会乱跳。
- sdk 基址必须页对齐且 > 0x10000。
- 所有 IPC 调用都推迟到每帧 tick 里，不在碰撞/伤害钩子里做，避免重入。
- 日志：`world_rumble_init`（首次解析结果）与 `world_rumble`（每次触发）。
